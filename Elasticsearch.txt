Elasticsearch est un moteur de recherche et d’analytique distribué basé sur Apache Lucene. Depuis sa sortie en 2010, Elasticsearch est rapidement devenu le moteur de recherche le plus populaire. Il est couramment utilisé pour l'analytique des journaux, la recherche en texte intégral, la veille sécuritaire, l'analytique commerciale et l'intelligence opérationnelle.

Elasticsearch est un moteur de recherche et d’analyse open source qui s’appuie sur la bibliothèque Apache Lucene. Les développeurs peuvent utiliser Elasticsearch pour ajouter des capacités de recherche extrêmement évolutives à leurs applications.


Initialement lancé en 2010 par Elastic, Elasticsearch a été conçu comme une solution distribuée en Java pour apporter des fonctionnalités de recherche plein texte dans des documents JSON sans schéma à travers différents types de bases de données.

Apache Lucene est une bibliothèque de moteur de recherche libre et open source, entièrement écrite en Java. Lucene est surtout reconnue pour son implémentation des moteurs de recherche. Plusieurs projets, tels qu’Elasticsearch, étendent ses capacités.



Recherche avec Curl :
-------------------
option -d = data

curl -XPUT 'localhost:9200/get-together/_doc/1?pretty' -H 'Content-Type: application/json' -d '{"name": "Elasticsearch Denver", "organizer": "Lee"}'

vérifier le contenu de index
http://localhost:9200/get-together?pretty 
curl -GET 'http://localhost:9200/get-together?pretty'

Voir ou récupérer le mapping
http://localhost:9200/get-together/_mapping/_doc?pretty
en env de prod, il faut avoir un schema fixe, ne pas utiliser le mapping par defaut


Requete de Recherche: tous les documents qui font référence au mot clé elasticsearch
http://localhost:9200/get-together/_doc/_search?q=elasticsearch&pretty 
curl -XGET 'http://localhost:9200/get-together/_doc/_search?q=elasticsearch&pretty' 

Recherche Multi index
http://localhost:9200/get-together,other-index/_doc/_search?q=elasticsearch&pretty 
curl -XGET 'http://localhost:9200/get-together,other-index/_doc/_search?q=elasticsearch&pretty'

with ignore_unavailable flag
http://localhost:9200/get-together,other-index/_doc/_search?q=elasticsearch&ignore_unavailable=true&pretty 
curl -XGET 'http://localhost:9200/get-together,other-index/_doc/_search?q=elasticsearch&ignore_unavailable=true&pretty'

Recherche dans tous les index
http://localhost:9200/_search?q=elasticsearch&pretty 
curl -XGET 'http://localhost:9200/_search?q=elasticsearch&pretty'


Recherche avec body pour requetes complexes
-------------------------------------------
curl -XPOST 'localhost:9200/get-together/_doc/_search?pretty' -H 'Content-Type: application/json' -d '{"query": {"query_string":{"query":"elasticsearch"}}}'

Recherche avec body et default field operator: default name, default operator
curl -XPOST 'localhost:9200/get-together/_doc/_search?pretty' -H 'Content-Type: application/json' -d '{"query": {"query_string":{"query":"elasticsearch san francisco", "default_field":"name", "default_operator":"AND"}}}'

Recherche avec la query term
curl -XPOST 'localhost:9200/get-together/_doc/_search?pretty' -H 'Content-Type: application/json' -d '{"query": {"term":{"name":"elasticsearch"}}}'

Recherche avec body et filtre
curl -XPOST 'localhost:9200/get-together/_doc/_search?pretty' -H 'Content-Type: application/json' -d '{"query":{"bool":{"filter":{"term":{"name":"elasticsearch"}}}}}'

Recherche aggrégation
curl -XPOST 'localhost:9200/get-together/_doc/_search?pretty' -H 'Content-Type: application/json' -d '{"aggregations":{"organizers":{"terms":{"field":"organizer"}}}}'

curl -XPUT 'localhost:9200/get-together/_mapping/_doc?pretty' -H 'Content-Type: application/json' -d '{
  "properties": {
    "organizer": { 
      "type":     "text",
      "fielddata": true
    }
  }
}'

Recuperer un document avec son ID
http://localhost:9200/get-together/_doc/1?pretty 
ou curl -GET 'http://localhost:9200/get-together/_doc/1?pretty'



Interpretation des resultats:
-----------------------------
took : temps d'exécution de la recherche e ms
_shard : nombre de fragments qui ont répondu à la requête
failed : nombre de fragment qui étaient down (0 = tous les fragments qui contenanit notre ducument ont pu répondre)
hits : dans cet attrubut que se trouve les documents
score: score du document, score de pertinance
